OpenCode's [V1-to-V2 guide](https://opencode.ai/docs/migrate-v1/) documents the config transition; V2 supports native `mcp.servers`, project agents and skills. Its [MCP server docs](https://opencode.ai/docs/mcp-servers/) define millisecond timeout values and the `legacy`, `auto`, and `2026-07-28` protocol modes. The probe initially set 20 ms, then passed after correcting it to 20,000 ms. The [permissions guide](https://opencode.ai/docs/permissions/) defines `webfetch`/`websearch` actions and ordered `deny` rules. The local catalog-disable setting `OPENCODE_DISABLE_MODELS_FETCH=1` is identified by an OpenCode maintainer in [issue #34730](https://github.com/anomalyco/opencode/issues/34730). OpenCode's [global update setting](https://opencode.ai/docs/config/) says project-level update values are ignored; the `OPENCODE_DISABLE_AUTOUPDATE` variable is described in [OpenCode's environment guidance](https://github.com/anomalyco/opencode/issues/55308).

## Test isolation

The V2 runtime probes used an isolated temporary project, OpenCode data/config directories, no credentials, a deterministic loopback-only OpenAI-compatible stub, and a macOS Seatbelt profile that permitted loopback service traffic and denied all other networking. The stub scripted the `skill` call and final answer; it did not judge behavior. In the run without `OPENCODE_DISABLE_MODELS_FETCH=1`, OpenCode logged the denied catalog lookup. With the variable set, that log event was absent. This log check is not packet capture or company endpoint-monitor evidence.

The MCP SDK and standard-library fixtures each passed actual OpenCode discovery/list/call flows under the same loopback-only policy. The provider was deterministic and scripted, so these are integration traces rather than agent reasoning or performance evidence. No company config, MCP endpoint, internal model, company source, or company data was used.

## Exact next evidence

If the company uses OpenCode desktop, disable or network-block its separate updater. Repeat the SDK/standard synthetic discovery and call on the company build and approved native Windows/Linux targets. Pilot performance evidence still requires matched company OpenCode tasks; no uplift claim is supported by this scripted local model.
