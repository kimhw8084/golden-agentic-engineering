INTENT, PRINCIPLES, BOUNDARIES

The Golden design

A fast engineering system uses the strongest agentic capabilities available and keeps proof, release, and production boundaries clear.

DRAFT / PILOT
WHY WE ARE DOING THIS

Make useful engineering work easier to start, easier to finish, and easier to trust.

Give the team a clear way to use OpenCode's agents, skills, and authorized MCP integrations; choose command-line tools by measured fit; keep deterministic checks authoritative; and make the system's actual status visible.

01

Agentic first

Discover installed agents, skills, and approved MCP capabilities. Exercise the strongest relevant workflow before recommending command-line tools.

02

Evidence decides

Compare agentic, CLI, and hybrid paths on the same acceptance criteria. Prefer per operation; do not crown a category by habit.

03

Fast without fake proof

Let agents reason and work. Let tests and deterministic checkers report what they actually ran. Unknown stays unknown.

04

Company boundaries

Use only approved data sources and internal services. No public runtime dependency, prompt telemetry, or production operation by default.

NO INSTALL ACTION TAKEN
FIRST: OFFLINE INSPECTION

Doctor before any runtime launch.

Run the local doctor to inspect versions from approved inventory, config key names, file collisions, and staged assets. It never executes OpenCode or makes a network request. Keep OpenCode closed until its no-public-egress behavior has been reviewed and verified.

python scripts/company_bootstrap.py doctor --opencode-version <LOCAL_INVENTORY_VERSION> --out <DOCTOR_JSON>

Do not include provider values or secret environment values in the doctor report. If version or compatibility is unknown, stop before Step B.

Read exact Windows and Linux commands
01

Read the design and qualify the runtime

Record what is available, missing, incompatible, or unapproved. Keep the provider/model settings intact.

02

Pick one real task with observable acceptance

Use an authorized fixture or synthetic data; agree what a correct, usable result means.

03

Exercise the best-fit agentic workflow

Use the primary agent plus a relevant skill. Add a specialist agent and approved MCP tool where useful; record actual calls and results.

04

Compare CLI and hybrid options

Run relevant candidates against the same criteria. Choose the best tool per operation based on outcome, rework, time, safety, and reproducibility.

05

Install only after compatibility review

Dry-run the collision-safe installer against the actual existing config directory. Review conflicts before applying.

06

Measure a small pilot

Compare accepted outcomes and time on one new and one existing app. Record limitations instead of claiming team qualification.
