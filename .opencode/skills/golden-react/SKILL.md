# React + TypeScript + Tailwind + shadcn/ui

1. Inspect existing internal shadcn package, components and approved offline dependencies before selecting new packages. Never run remote shadcn installers on the intranet.
2. Map user tasks and data/permissions first, then reusable components and state transitions.
3. Enforce strict black/white/gray. Distinguish scientific chart categories with labels, line styles, patterns and shapes rather than relying on color.
4. Reuse the approved design-token source. When extending it, separate primitive values, purpose-based semantic names, and component aliases; update the real Tailwind/shadcn token source instead of scattering one-off values. This compact token rule adapts a reworded method from the bounded [UI/UX Pro Max source review](../../../research/ui-ux-pro-max-audit.md).
5. Use mathematically consistent spacing/typography, compact desktop-first density, responsive constraints and keyboard navigation. Verify concrete layouts in real browser widths.
6. Every applicable control needs behavior contract: default/hover/focus/disabled/loading/error/empty/success; selection/edit/copy/paste/data import; destructive delete inline-confirm, irreversible/unsaved changes app-native confirmation; avoid accidental loss.
7. AI global assistant plus contextual actions: read-only responses normally display; persistent changes preview and confirmation based on risk. Feedback optional and non-blocking.
8. Verify TypeScript typecheck, unit/component tests, interaction workflows, accessibility and manual task-completion review. Do not claim Playwright readiness until its offline browser binary is qualified.
9. Capture evidence and documentation impact; keep generated code consistent with project profile and Golden version.
